## Этап 5: Анализ визуализации

### Примеры визуализации для трех различных пакетов:
Для проверки работы скрипта были сгенерированы SVG-графы для трех разных библиотек при `max_depth = 2`:
1. `express@4.19.2`
2. `react@18.2.0`
3. `lodash@4.17.21`

### Сравнение со штатными инструментами
Если сравнить полученные графы с командой `npm ls --all` (которая визуализирует дерево в терминале), видны следующие расхождения:

1. **Хоистинг (Поднятие зависимостей):** `npm` оптимизирует установку, перемещая дублирующиеся зависимости транзитивных пакетов на верхний уровень дерева (`node_modules`). Наш инструмент строит строгий концептуальный граф.
2. **Lock-файлы:** Менеджер npm опирается на `package-lock.json`, который жестко фиксирует версии. Наш скрипт просто парсит строку semver и берет базовую версию из реестра (или `latest`).
3. **Отсутствие Dev/Peer-зависимостей:** Наш скрипт парсит только секцию `dependencies` согласно задаче, тогда как npm при локальной установке без флага `--omit=dev` разрешает и другие типы зависимостей.
4. **Фиксированная глубина:** Наш граф ограничивается жестким параметром `max_depth`, обрезая ветки, которые npm обрабатывает до конца.
